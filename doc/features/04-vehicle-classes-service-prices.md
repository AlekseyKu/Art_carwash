# Фича 04: Классификация авто + цены услуг по классу

**Статус:** implemented (локально)  
**Связано:** вкладки каталога (`catalog_tabs`: Услуги / Товары), касса `PosPage`, админка `AdminPage`

## Цель

Один и тот же список **услуг мойки**, но **разная цена** в зависимости от класса автомобиля. На кассе мойщик выбирает класс — на кнопках услуг сразу показываются цены этого класса. **Товары** (кофе и т.п.) остаются с одной ценой, без классификации.

## Модель

- **Услуги** = справочник названий (без цены в UI).
- **Классификация** = справочник классов авто.
- **Цены** = матрица «услуга × класс» (`service_prices`).
- **Товары** = как сейчас: `name` + одна `price_kopecks`, классификация не применяется.

Не дублируем услуги по классам — только цены.

| 1 | Класс по умолчанию | **Легковые** |
| 2 | Нет цены для услуги×класс | **Скрыть** услугу на кассе для этого класса |

| 6 | Кнопки на кассе | Иконки из `source/icons/1.png`…`5.png` (см. таблицу ассетов) + кнопка **«i»** → описание / марки авто |

## 1. Админка

Порядок пунктов:

1. **Услуги** — только название (+ вкл/выкл, порядок, удаление). **Цены убрать.**
2. **Классификация авто** — NEW.
3. **Цены на услуги** — NEW.
4. **Товары** — название + цена (как сейчас).
5. Далее: Вкладки, Скидки, Мойщики, …

> «Услуги» / «Товары» — динамические `catalog_tabs`.  
> «Классификация» и «Цены» — **fixed-вкладки** админки.

### 1а. Классификация авто

- Список: название, описание (модели), порядок, активна, удалить.
- Форма: название + описание (экранная клавиатура).
- Seed 5 классов при миграции, если таблица пуста.

### 1б. Услуги

- Без колонки «Цена».
- Добавление: только название.
- Старые `price_kopecks` услуг → в `service_prices` только для класса **Легковые**; у услуги в `services` для tab=services цену на кассе не читать.

### 1в. Цены на услуги

- Подпункты (табы) по классам.
- Внутри класса: список услуг + поле цены (тач-клавиатура).
- Пустая / удалённая цена → на кассе услуга для этого класса **не показывается**.

## 2. Касса

Тулбар:

```
[📋 заказы]  [1][2*][3][4][5]  [ⓘ]
              ↑ PNG-иконки     ↑ описание
              классов из
              source/icons
```

- Кнопки классов — **PNG из `source/icons`** (маппинг 1→Маленькие … 5→Автобусы), без длинного текста на кнопке; активный класс подсвечен.
- По умолчанию выбран **Легковые** (`2.png` / `sedan`).
- Кнопка **«i»**: попап/drawer с **названием и описанием** (марки) — как минимум для **текущего** класса; удобно показать список всех классов с описаниями.
- Вкладка **Услуги**: только услуги с ценой для выбранного класса; на чипе — цена из матрицы.
- Вкладка **Товары**: без изменений, класс не влияет.
- **Смена класса** → обновить `orders.vehicle_class_id` → **пересчитать** `price_kopecks` у позиций-услуг в черновике по новой матрице → пересчитать итог. Позиции без цены в новом классе — убрать из чека (или обнулить qty) с понятным UX.
- В `order_items` — снимок цены; на заказе — `vehicle_class_id` + `vehicle_class_name`.

## Модель данных

### `vehicle_classes`

| Поле | Тип | |
|------|-----|---|
| id | TEXT PK | |
| slug | TEXT UNIQUE | `small`, `sedan`, … |
| name | TEXT | «Легковые» |
| description | TEXT | модели / подсказка |
| icon_key | TEXT | ключ иконки: `small`…`bus` → `source/icons/1.png`…`5.png` |
| sort_order | INTEGER | |
| active | INTEGER | |

### `service_prices`

| Поле | Тип | |
|------|-----|---|
| service_id | TEXT | → services.id |
| class_id | TEXT | → vehicle_classes.id |
| price_kopecks | INTEGER | |
| PK | (service_id, class_id) | |

### Изменения существующих

- `services.price_kopecks` — источник цены для **товаров**; для **услуг** после миграции не используется на кассе.
- `orders.vehicle_class_id` TEXT NULL, `orders.vehicle_class_name` TEXT NULL.
- Резолв цены услуги при save/reprice: `service_prices` по классу заказа.

### Миграция

1. Создать таблицы + seed 5 классов (`sedan` = Легковые — default).
2. Для каждой услуги (`tab = services`): INSERT текущий `price_kopecks` **только** в класс Легковые.
3. Товары не трогать.
4. У существующих draft-заказов выставить `vehicle_class_id` = Легковые.

## API (эскиз)

| Метод | Путь | Описание |
|-------|------|----------|
| GET | `/api/catalog?classId=` | Классы + услуги с ценой только для classId (без цены — не отдавать); товары как сейчас |
| GET/POST/PUT/DELETE | `/api/admin/vehicle-classes` | CRUD классов |
| GET | `/api/admin/service-prices?classId=` | Цены услуг для класса |
| PUT | `/api/admin/service-prices` | Сохранить цены `{ classId, items: [{ serviceId, priceKopecks \| null }] }` |
| PUT | `/api/orders/:id/vehicle-class` | Сменить класс + **пересчёт** позиций услуг |
