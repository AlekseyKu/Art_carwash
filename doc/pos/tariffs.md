# Фича: Тарифы / спец.цены клиентов

**Статус:** in-progress (реализация)  
**Связано:** `AdminPage` (каталог), `ClientsPage`, касса `PosPage` / резолв цен, PWA `CabinetPage`, [vehicle-classes.md](vehicle-classes.md), [../pwa/customer-app.md](../pwa/customer-app.md)

## Цель

Именованные **тарифы** (напр. «Такси-2026») с фиксированными спец.ценами на выбранные услуги/доп. для выбранных классов авто, с периодом действия. Тариф назначается одному или нескольким клиентам. На кассе при привязке клиента цена подставляется автоматически. В ЛК PWA клиент видит свой тариф и список спец.цен.

---

## Зафиксированные решения

| # | Тема | Решение |
|---|------|---------|
| 1 | Сущность | Именованный **тариф** + период `valid_from`…`valid_to` (дни MSK; `valid_to` NULL = бессрочно) + флаг `active` |
| 2 | Где создавать | **Админ → Скидки и тарифы → Тарифы** и **карточка клиента**: создать новый или выбрать существующий. Все тарифы видны в админке |
| 3 | Оверрайды | В тарифе задаются **только** замены: класс × услуга/доп. × цена ₽. Не выбранные позиции → матрица `service_prices` |
| 4 | Назначение | M:N: один тариф → много клиентов; у клиента может быть несколько тарифов |
| 5 | Касса | При привязке клиента (и смене класса) — автопересчёт позиций услуг/доп. по резолву. Отдельного UI «выбрать тариф» на кассе нет |
| 6 | Товары | **Не** входят в тариф |
| 7 | Конфликт | Если у клиента несколько активных тарифов с оверрайдом на одну `(service, class)` → берём **минимальную** цену |
| 8 | PWA ЛК | Блок «Ваш тариф»: имя, период, список спец.цен (услуга · класс · цена). Вне периода / без назначения — блок скрыт |
| 9 | Source of truth | Тарифы и назначения — **local**; в cloud — snapshot + зеркало для ЛК (телефон = связь с `clients`) |

## Резолв цены на кассе

Для позиции вкладки Услуги / Доп.услуги при известном `classId` и опциональном `clientId`:

1. Клиент привязан → назначенные тарифы с `active = 1`, у которых сегодня (календарный день MSK) ∈ `[valid_from, valid_to]` (`valid_to` NULL → верхней границы нет).
2. Среди этих тарифов ищем строки `tariff_prices` для `(serviceId, classId)`.
3. Если есть совпадения → цена = **min(price_kopecks)**.
4. Иначе → `service_prices` как сейчас ([vehicle-classes.md](vehicle-classes.md)).
5. Далее без изменений: коэффициент строки, скидка % на строку, каталожная скидка заказа.

```
Добавить услугу
      │
      ▼
Клиент + тариф в периоде? ──нет──► service_prices
      │ да
      ▼
Есть tariff_prices (service×class)? ──нет──► service_prices
      │ да
      ▼
min(оверрайды) → цена строки
```

Смена клиента / класса / состава тарифа → пересчёт draft-позиций услуг/доп. (товары не трогать). В `order_items` — снимок итоговой цены, как сейчас.

## Модель данных (local SQLite)

### `tariffs`

| Поле | Тип | |
|------|-----|---|
| id | TEXT PK | |
| name | TEXT NOT NULL | «Такси-2026» |
| valid_from | TEXT NOT NULL | дата `YYYY-MM-DD` (день MSK) |
| valid_to | TEXT NULL | `YYYY-MM-DD` или NULL = бессрочно |
| active | INTEGER NOT NULL DEFAULT 1 | |
| created_at / updated_at | TEXT | |

Инвариант UI: `valid_to` ≥ `valid_from`, если задан.

### `tariff_prices`

| Поле | Тип | |
|------|-----|---|
| tariff_id | TEXT | → tariffs.id |
| service_id | TEXT | → services.id (только tabs Услуги / Доп.) |
| class_id | TEXT | → vehicle_classes.id |
| price_kopecks | INTEGER NOT NULL | ≥ 0 |
| PK | (tariff_id, service_id, class_id) | |

Пустая ячейка в UI = строки нет (нет оверрайда). Удаление оверрайда = DELETE строки.

### `client_tariffs`

| Поле | Тип | |
|------|-----|---|
| client_id | TEXT | → clients.id |
| tariff_id | TEXT | → tariffs.id |
| PK | (client_id, tariff_id) | |

Назначение/снятие не удаляет сам тариф.

## UI

### Админ → Скидки и тарифы → Тарифы

Подменю раздела (**Скидки** / **Тарифы**): `Тарифы` (`tab === "tariffs"`).

**Список:**
- название, период (текст вида `01.01.2026 — 31.12.2026` / `с 01.01.2026`), число оверрайдов, число клиентов;
- Вкл / Выкл, **Изменить**, **Удалить** (confirm; каскад prices + client_tariffs).

**Форма создания / правки:**
1. Название, период (from / to, to опционально), active.
2. Оверрайды: выбор класса (табы как в «Цены на услуги») → список услуг и доп. с полем цены ₽; пусто = нет оверрайда.
3. Клиенты тарифа: поиск / добавить / снять (те же `clients`).

Сохранение → local API + при необходимости триггер `catalog.snapshot` (определения тарифов для cloud/PWA).

### Карточка клиента (`ClientsPage`)

Секция **Тарифы**:
- чипы назначенных тарифов (имя + краткий период); снять назначение;
- **Выбрать существующий** — picker из всех тарифов;
- **Создать тариф** — тот же редактор (имя, период, оверрайды) → сохранение в `tariffs` + сразу `client_tariffs` для текущего клиента. Тариф появляется в админке.

### Касса

Без отдельного переключателя тарифа. После привязки клиента цены на кнопках услуг/доп. и в draft отражают резолв. Подсказка (опционально v1): бейдж имени тарифа рядом с клиентом, если есть активный в периоде.

### PWA — личный кабинет

Блок **«Ваш тариф»** (один или несколько активных в периоде):
- название, период;
- раскрываемый список: услуга · класс · цена.

Нет активных назначений / все вне периода → блок не показывать. Клиент тариф **не** редактирует.

## Sync / cloud

| Что | Куда | Как |
|-----|------|-----|
| Определения тарифов + prices | cloud | в `catalog.snapshot` (массив `tariffs`) |
| Назначения client ↔ tariff | cloud | по телефону: при sync клиента / `customer.upsert` зеркало `customer_tariffs` (или вложение в customer DTO) |
| ЛК | PWA | `GET /api/customer/me` → `tariffs: [{ id, name, validFrom, validTo, prices: [{ serviceName, className, priceKopecks }] }]` только активные в периоде |

Source of truth назначений на станции — local `client_tariffs`. Cloud нужен для отображения в PWA.

## API (эскиз)

### Local — админ / клиенты

| Метод | Путь | Описание |
|-------|------|----------|
| GET | `/api/admin/tariffs` | список (+ counts) |
| GET | `/api/admin/tariffs/:id` | тариф + prices + clientIds |
| POST | `/api/admin/tariffs` | создать `{ name, validFrom, validTo?, active?, prices[], clientIds? }` |
| PUT | `/api/admin/tariffs/:id` | обновить |
| DELETE | `/api/admin/tariffs/:id` | удалить |
| PUT | `/api/clients/:id` | body включает `tariffIds[]` (или отдельный `PUT …/tariffs`) |

### Local — касса / каталог

| Метод | Путь | Описание |
|-------|------|----------|
| GET | `/api/catalog?classId=&clientId=` | цены услуг/доп. уже с учётом тарифа клиента (если передан) |
| PUT | `/api/orders/:id` / client / vehicle-class | при смене клиента или класса — reprice услуг/доп. по резолву |

### Cloud — клиент

| Метод | Путь | Описание |
|-------|------|----------|
| GET | `/api/customer/me` | + `tariffs[]` для ЛК (см. выше) |

## Тест-план

- [ ] Создать тариф в админке с оверрайдом на одну услугу одного класса; остальные услуги — матрица  
- [ ] Назначить двум клиентам; снять у одного — у второго цены тарифа остаются  
- [ ] Создать тариф из карточки клиента → виден в Админ → Тарифы и назначен клиенту  
- [ ] Период: до `valid_from` и после `valid_to` — матрица; внутри — оверрайд; `valid_to` NULL — бессрочно  
- [ ] `active = 0` — как отсутствие тарифа  
- [ ] Два тарифа на одном клиенте с разными ценами на одну услугу → на кассе min  
- [ ] Смена класса / клиента на кассе → пересчёт draft  
- [ ] Товары не меняются тарифом  
- [ ] Коэффициент и скидка % на строку считаются от цены после тарифа  
- [ ] PWA ЛК: виден активный тариф и цены; вне периода / без назначения — блок скрыт
