# Фича 06: Клиентское PWA «Автомойка у ЖД»

**Статус:** фаза A–B — в коде (локально); фаза C — решения зафиксированы (ниже), в работе  
**Связано:** cloud-api, local-api catalog/clients, касса `PosPage` / `ClientSidePanel`, отчёты `/reports`, бренд [06-brand.md](../06-brand.md), бэклог G2/G4/A5 ([03-backlog-ideas.md](03-backlog-ideas.md))

Клиенты в интернете **не ходят на кассу**. Касса и админка — local-first на мини-ПК. PWA работает через **cloud-api**; каталог и записи синхронизируются со станцией. Оплата в первой поставке с записью — **только на мойке**.

Публичное имя в PWA: **«Автомойка у ЖД»** (г. Ступино). Внутренний бренд/репозиторий «Автомойка АРТ» не меняем.

---

## Цель

Отдельное мобильное PWA для клиента мойки:

1. Онбординг: сплэш → описание → регистрация (телефон + пароль **и** согласие на ПДн на одном экране).
2. Прайс-лист из админки (цены по классу авто, как на кассе).
3. Запись на мойку (1 основная услуга + несколько доп.); календарь слотов на кассе.
4. Личный кабинет: профиль (телефон + имя), несколько авто (госномер, класс); история записей — фаза C.
5. Собственник: `/reports` + **скрытый вход в PWA** (пароль owner) — смотреть ленту и проверять UX клиента.

Новое приложение `apps/pwa` (Vite + React + `vite-plugin-pwa`). **Не** смешивать с kiosk-UI кассы в `apps/web`. Шрифт Montserrat. Цвета PWA — **тёмно-красный + графит `#303236`** (набор «Гранат» в [06-brand.md](../06-brand.md)); киоск пока на фиолетовом.

### Нормализация телефона (клиент)

- Хранить и сравнивать: `+7` + 10 цифр (`+79852741430`).
- Ввод: маска РФ; `8XXXXXXXXXX` → `+7…`; пробелы/скобки отбрасывать.

### Нормализация госномера (гараж / касса)

- Хранить и сравнивать: только **цифры и заглавные кириллические буквы** серии РФ (А, В, Е, К, М, Н, О, Р, С, Т, У, Х).
- Пример канонического вида: `А170РТ90`.
- Ввод: trim; нижний регистр → верхний; пробелы, дефисы и прочие разделители отбросить.
- Невалидный формат → ошибка валидации (не сохранять).

## Архитектура

```
[PWA клиент] ──► [cloud-api] ◄── тот же VPS (Docker)
                    ▲     │
     каталог, клиенты│     │ записи, профили
                    │     ▼
[Касса / Админ] ──► [local-api] ──► SQLite станции
```

Источник правды:

| Данные | Где правда | Sync |
|--------|------------|------|
| Каталог, часы, длительности услуг, правила записи | Станция (админка) | local → cloud (снимок) |
| Аккаунт клиента, гараж, записи из PWA | Cloud | cloud → local (pull) |
| Оплата, чек, смена | Станция (касса) | order.paid → cloud |

Конфликты: оплаченный локальный заказ = source of truth. Запись из PWA не проводит оплату.

## Онбординг при старте

Приложение **не пускает в меню**, пока клиент не создал аккаунт (или не вошёл).

Повторный запуск: сплэш → сразу три вкладки (сессия сохранена).  
Нет сессии: сплэш → вход (телефон + пароль), **без** повторных тезисов.

```
Запуск → 0. Сплэш
            ├─ сессия есть ──────────────► три вкладки
            └─ сессии нет
                  ├─ первый запуск ──► 1. Тезисы → 2. Регистрация + ПДн → вкладки
                  └─ онбординг уже был ► Вход / регистрация (+ ПДн, если новый аккаунт)
```

### 0. Сплэш (каждый запуск)

- Полноэкранно, название **«Автомойка у ЖД»**, фон графит `#303236`, акцент — тёмно-красный.
- Пока грузятся shell, Montserrat, проверка сессии; каталог — **после** входа.
- Минимум ~0.8–1.2 с. Нет кнопок, нет скипа.

### 1. Тезисное описание (только первый запуск)

Один экран, 3 тезиса: Прайс / Запись / Кабинет. «Далее» → регистрация. «У меня уже есть аккаунт» → вход.

### 2. Регистрация + согласие на ПДн (один экран)

- Телефон РФ (`+7`), пароль + повтор (≥ 8 символов), bcrypt на сервере.
- Чекбокс ПДн обязателен; ссылка на [политику](06-privacy-policy.md); `privacy_policy_version = 2026-08-30`.
- В аккаунте: `pdn_accepted_at`, версия, телефон.
- «Забыли пароль» — фаза D.

## 1. PWA: три экрана (нижняя навигация)

```
┌─────────────────────────────┐
│  контент вкладки            │
├──────────┬─────────┬────────┤
│  Прайс   │ Запись  │Кабинет │
└──────────┴─────────┴────────┘
```

### 1.1 Прайс-лист

- Данные из админки: `catalog_tabs`, услуги, товары, `service_prices` по классу.
- Класс авто — те же классы и иконки, что на кассе.
- Пустая цена → услуга **скрыта**.
- Товары — одна цена.
- Офлайн: SW кэширует последний прайс.
- Блок «О мойке»: город, часы, телефон (tap-to-call), **«Построить маршрут»** → Яндекс.

### 1.2 Календарь / запись

- Авто из гаража (или класс + госномер) → **1 основная услуга** → доп.услуги (несколько) → дата → свободный слот (**только время**).
- Слоты: 09:00–21:00 MSK ежедневно × длительность (main + addons) × **1 линия**; шаг сетки 15 мин.
- Правила (дефолты; все — в админке кассы): горизонт **14** дн., мин. запас **4** ч., отмена до **1** ч.; duration: услуги **60** / доп. **15** мин (колонка «Время» в «Цены на услуги»).
- Статусы: `booked` → `arrived` → `in_service` → `completed` | `cancelled` | `no_show`.
- Оплата на мойке. Бронь с кассы и из PWA — одна занятость.

### 1.3 Личный кабинет

- **Профиль:** телефон = логин (**не менять** в v1); **имя** — редактируемое (`PUT /api/customer/me`). Выход.
- **Гараж:**
  - список авто (госномер + класс + опциональная кличка);
  - добавить / редактировать / удалить;
  - флаг **«по умолчанию»** — одно на клиента; **всегда первым** в списке;
  - госномер: РФ-валидация и нормализация (см. выше).
- **История записей и моек** — **не в фазе B**; появляется в **фазе C** (после календаря/записи); повтор набора → экран записи.

### 1.4 Скрытый вход собственника

- Не в нижнем меню. Путь/жест: например `/owner` или длинный тап по логотипу на сплэше.
- Вход: **пароль собственника** (тот же, что `/reports` / `POST /api/owner/login`).
- Экран: лента записей дня/недели + ссылка «открыть как клиент» (проверка UX). Оплату не проводит.

## 2. Касса и админка на станции

CRM на кассе сейчас выключена (`ClientSidePanel` не монтируется), календаря нет.

### 2.1 Календарь дня на кассе

```
Время    Слот
09:00    [Иванов · запись]
09:30    [свободно]
10:00    [заказ / бронь с кассы]
```

- **v1: одна колонка** (одна линия). Клиент в PWA видит ту же занятость по времени.
- «Прибыл» → позиции записи в **черновик заказа** → оплата.
- Walk-in vs бронь; пересечения — предупреждение.
- После оплаты: `bookings.local_order_id` + `completed`.

### 2.2 Клиенты на кассе

**Поиск на экране кассы (`PosPage`):**
- Поле поиска по **телефону или госномеру** — рядом с иконкой **i** (информация по классификации авто), в ряду классов.
- Результат: подставить клиента / авто в заказ (класс, номер, телефон при наличии).

**Страница «Клиенты» (фаза B):**
- Отдельный раздел в UI кассы/админки (не только боковая ANPR-панель).
- Список клиентов; поиск по телефону / госномеру.
- Добавить / править: имя, телефон, авто гаража (несколько; те же правила номера, что в PWA).
- История визитов/заказов — по возможности из local `orders` (полная история записей cloud — с фазы C).
- Панель `ClientSidePanel` / ANPR не обязательна для B; поиск на кассе + страница клиентов — must-have.

### 2.3 Админка станции (доработка кассы)

Настройки (фаза C, но поля заложить в схему раньше):

| Параметр | Дефолт | Где |
|----------|--------|-----|
| Часы работы по дням + исключения | **v1: жёстко 09:00–21:00 ежедневно MSK** | позже — Админ → расписание |
| `duration_minutes` у услуг / доп. | Услуги **60**, доп. **15** | **Цены на услуги → колонка «Время»** |
| Горизонт записи (дней) | 14 | Админ → запись |
| Мин. запас до слота (часов) | 4 | Админ → запись |
| Отмена клиентом за N часов | 1 | Админ → запись |
| Блокировка слотов | — | Админ → запись |
| Контакты «О мойке» | см. таблицу выше | Админ → настройки сайта |

Каталог редактируется только на станции → `catalog.snapshot` в cloud.

### Миграция local `clients`

1. Телефон = идентичность (матч с `customer_accounts.phone`).
2. Госномера → `vehicles`.
3. Старый `plate_number` → первое авто.
4. Поиск на кассе — телефон или любой номер гаража.

### Outbox / sync

| Тип | Направление | Когда |
|-----|-------------|-------|
| `catalog.snapshot` | local → cloud | save в админке |
| `customer.upsert` | cloud → local | регистрация / гараж |
| `booking.upsert` | cloud → local | запись |
| `booking.status` | local → cloud | прибыл / completed / no-show |
| `order.paid` | local → cloud | + phone, plates, customer_id |

| Что | URL |
|-----|-----|
| PWA | `https://carwash-jd.ru/` |

### Рекомендация: один `docker compose`

На 1 ГБ RAM не поднимать лишнее. Достаточно:

```
┌─ carwash-jd.ru → 176.124.201.150 ─────────┐
│  Caddy :80/:443 (Let's Encrypt)           │
│    ├─ /          → static apps/pwa/dist   │
│    └─ /api/*     → cloud-api :3002        │
│  cloud-api (Node) + volume SQLite         │
└───────────────────────────────────────────┘
```

| Сервис | Образ / роль | Заметки для 1 ГБ |
|--------|--------------|------------------|
| **caddy** | reverse proxy + HTTPS (Let's Encrypt) | Легче nginx+certbot для старта |
| **pwa** | static: либо stage в volume Caddy, либо tiny `nginx:alpine` только со static | Не нужен Node в runtime |
| **cloud-api** | Node 22 slim, `PORT=3002` | Один процесс; SQLite на volume |

**Почему так:**

- Один compose = один `docker compose up -d` после сборки.
- PWA — статика; cloud-api — единственный stateful сервис.
- Касса (local-api / Electron) **не** на этом VPS.
- Sync с мойки: касса шлёт outbox на `https://carwash-jd.ru/api/sync` (тот же cloud-api).

**Структура в репо (при реализации фазы A):**

```
deploy/
  docker-compose.yml
  Caddyfile
  cloud-api.Dockerfile
```

Эскиз compose:

```yaml
services:
  caddy:
    image: caddy:2-alpine
    ports: ["80:80", "443:443"]
    volumes:
      - ./Caddyfile:/etc/caddy/Caddyfile
      - pwa_dist:/srv/pwa:ro
      - caddy_data:/data
    depends_on: [cloud-api]

  cloud-api:
    build:
      context: ../
      dockerfile: deploy/cloud-api.Dockerfile
    environment:
      PORT: "3002"
      ART_OWNER_PASSWORD: ${ART_OWNER_PASSWORD}
      ART_SYNC_TOKEN: ${ART_SYNC_TOKEN}
    volumes:
      - cloud_data:/data
    restart: unless-stopped

  # pwa: собирается в CI/скрипте и копируется в volume pwa_dist
```

Caddyfile (эскиз):

```
carwash-jd.ru, www.carwash-jd.ru {
  encode gzip
  handle /api/* {
    reverse_proxy cloud-api:3002
  }
  handle {
    root * /srv/pwa
    try_files {path} /index.html
    file_server
  }
}
```

**Ресурсы:** лимит cloud-api ~256–384 МБ; Caddy ~50 МБ; запас ОС. Без Postgres/Redis.

**Секреты:** `.env` на сервере (`ART_OWNER_PASSWORD`, `ART_SYNC_TOKEN`), не в git. Sync token = тот же, что на кассе в настройках cloud URL.

**Бэкап:** volume SQLite cloud — ежедневный copy off-box.
