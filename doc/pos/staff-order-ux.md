# Фича 05: Операторы / мойщики, коэффициент, UX заказа и аналитика

**Статус:** shipped
  
**Релиз-кандидат:** POS **0.3.0**  
**Связано:** `AdminPage`, `PosPage`, `OnScreenKeyboard`, `orders` / `washers` / analytics в `local-api`

## Цель

Большой UX/продуктовый апдейт кассы и админки:

1. Не терять несохранённые правки цен при уходе с раздела «Цены на услуги».
2. Гибкая доплата к услуге на кассе через **коэффициент** (шаг ± ₽).
3. Разделить роли: **Оператор** (касса + смены) и **Мойщик** (персонал в заказе + % зарплаты).
4. Удобнее править скидки; аналитика «по мойщикам».
5. В заказе: ручные позиции, удаление строк, обязательный выбор мойщиков, коэффициент.
6. Экранная клавиатура: Shift (заглавные) + базовые символы.

---

## Зафиксированные решения

| # | Тема | Решение |
|---|------|---------|
| 1 | Коэффициент | **± шаг в ₽** к цене строки заказа (default шаг **50 ₽**). Каталог / матрица цен **не** меняются. |
| 2 | Коэффициент — отображение | В строке заказа текст вида **«Коэффициент +100 руб»** (фактическая сумма доплаты). Учитывается в **подытоге и итоге**. |
| 3 | Коэффициент — пол | При «−» **нельзя** опустить цену строки **ниже базовой** цены услуги для выбранного класса. |
| 4 | Коэффициент — где | Только **Услуги** и **Доп.услуги**. Товары — без коэффициента. |
| 5 | Мойщики в заказе | **Несколько** (мультивыбор). Выбор **обязателен** до оплаты. |
| 6 | Операторы | Текущие `washers` с PIN → UI **Операторы** (касса, смены). |
| 7 | Мойщики-персонал | Справочник: **имя**, active, **зарплата в %** (без PIN). |
| 8 | Аналитика по мойщикам | Выручка заказа при N мойщиках **делится поровну** (total/N каждому). Учитывать `salary_percent` для расчёта зарплаты (см. §1.5 / §1.6). |
| 9 | Dirty цен | Confirm **только при уходе** с раздела «Цены на услуги» на другой пункт админки. Внутри раздела (класс / Услуги↔Доп) dirty **держим в памяти**, без диалога на каждый таб. |
| 10 | Ручная позиция | Строка без каталожного `service_id` (manual): название + цена snapshot. |
| 11 | Скидки | Кнопка **Изменить** (как у услуг). |
| 12 | OSK | Shift + основные символы. |

## 1. Админка

### 1.1 Цены на услуги — dirty state + confirm

**Сейчас:** правки в памяти UI; без «Сохранить» теряются при уходе.

**Нужно:**

- Флаг `dirty` при любом изменении поля цены.
- Переключение класса авто / Услуги↔Доп.услуги **внутри** раздела: не показывать диалог; сохранять черновик правок в state (по classId+tabSlug или единый буфер с save текущего перед подгрузкой — на усмотрение реализации, главное не терять dirty без спроса).
- При уходе на **другой** пункт меню админки / logout при `dirty`:
  - диалог: **Сохранить** | **Не сохранять** | **Отмена**.
- Сохранить → `PUT /api/admin/service-prices` (для затронутых class/tab), затем навигация.
- Не сохранять → discard, навигация.
- Отмена → остаться на «Цены на услуги».

**UX:** индикатор «Есть несохранённые изменения».

### 1.2 Услуги / Доп.услуги — тумблер «Коэффициент»

- Тумблер **Коэффициент** (off по умолчанию).
- Если on → настройка **Шаг, ₽** (default **50**).
- Колонки на `services`:
  - `coefficient_enabled INTEGER NOT NULL DEFAULT 0`
  - `coefficient_step_kopecks INTEGER NOT NULL DEFAULT 5000`
- В catalog DTO: `coefficientEnabled`, `coefficientStepKopecks`.
- **Не** для товаров.

### 1.3 Скидки — «Изменить»

Кнопка **Изменить** → форма (имя, тип, значение) → **Сохранить** / **Отмена**.

### 1.4 Операторы (бывшие мойщики с PIN)

- **Настройки → Операторы**.
- Имя, PIN, active → доступ к кассе, open/close смены.
- Минимально: таблица `washers` + rename UI; login API совместим.

### 1.5 Мойщики (персонал заказа)

- **Настройки → Мойщики** (рядом с Операторами).
- Поля: **имя**, **зарплата %** (`salary_percent`, число 0–100), active, sort_order. **Без PIN.**
- Таблица `staff_washers`:
  - `id`, `name`, `salary_percent INTEGER NOT NULL DEFAULT 0`, `active`, `sort_order`
- Связь с заказом M:N: `order_staff_washers (order_id, staff_washer_id)`.

**Смысл %:** доля от **приписанной** мойщику выручки (после деления заказа поровну), для отображения в аналитике «к выплате» ≈ `(orderTotal / N) * salary_percent / 100` суммарно по заказам периода.

### 1.6 Аналитика — «по мойщикам»

Подрежим рядом с Период / Смены:

- Периоды:
  - **Смена** (default) — текущая или выбранная
  - **Неделя** (пн–вс)
  - **Месяц** (1-е — конец месяца)
  - **Выборочные даты** (from–to)
- Метрики на мойщика:
  - число заказов (где он в составе)
  - **выручка** = Σ (total_заказа / N_мойщиков_в_заказе)
  - **зарплата (оценка)** = Σ (выручка_доли × salary_percent / 100)
- Заказы без мойщиков в выборку by-washer не входят (на кассе выбор обязателен для новых оплат).

`GET /api/admin/analytics/by-washer?mode=shift|week|month|range&…`

## 2. Касса — правый блок «Заказ»

Порядок сверху вниз:

1. **Заказ** + кнопка **+** (справа)
2. Список позиций (удаление; у услуг/доп. с коэффициентом — ± и подпись доплаты)
3. **Мойщики** (мультивыбор, обязательно ≥1 перед оплатой)
4. **Скидка**
5. Подытог / скидка / итого
6. **Оплата** (disabled, если нет мойщиков или нет позиций)

### 2.1 Ручная позиция («+»)

- Ввод названия + цены ₽ (OSK).
- Строка `is_manual` / `service_id IS NULL`.
- Без коэффициента.

### 2.2 Удаление позиций

- Кнопка удалить на каждой строке → убрать из draft + persist.

### 2.3 Мойщики

- Чипы активных `staff_washers`.
- Мультивыбор; без выбранных — нельзя оплатить (сообщение).

### 2.4 Коэффициент

- Если `coefficientEnabled` у позиции-услуги:
  - кнопки **−** / **+** с шагом из админки;
  - `linePrice = basePrice + extra`, `extra ≥ 0`, кратно шагу (или накопление шагами);
  - подпись: **«Коэффициент +{extra} руб»** (если extra = 0 — можно скрыть или «Коэффициент +0 руб»);
  - `extra` и итоговая цена строки в snapshot `order_items`;
  - подытог/итог считают **итоговые** цены строк (уже с доплатой).

**Базовая цена** = цена из каталога для текущего класса (как при добавлении в заказ). Смена класса → пересчёт base; extra сохранить, если `base+extra` валиден, иначе clamp extra.

## Модель данных

```
services:
  + coefficient_enabled INTEGER NOT NULL DEFAULT 0
  + coefficient_step_kopecks INTEGER NOT NULL DEFAULT 5000

staff_washers:
  id TEXT PK
  name TEXT NOT NULL
  salary_percent INTEGER NOT NULL DEFAULT 0   -- 0..100
  active INTEGER NOT NULL DEFAULT 1
  sort_order INTEGER NOT NULL DEFAULT 0

order_staff_washers:
  order_id TEXT NOT NULL
  staff_washer_id TEXT NOT NULL
  PRIMARY KEY (order_id, staff_washer_id)

order_items:
  service_id NULLABLE          -- NULL = ручная
  + is_manual INTEGER DEFAULT 0
  + base_price_kopecks INTEGER -- опц., для clamp коэффициента
  + coefficient_extra_kopecks INTEGER DEFAULT 0
  -- price_kopecks = итог строки (base + extra) для расчёта чека

-- washers (pin_hash) = операторы кассы (без смены схемы login)
```

Миграции аддитивные; существующий каталог/заказы сохранить.

## Тест-план

- [ ] Цены: dirty → уход в другое меню → сохранить / discard / отмена; внутри табов цен — без лишних диалогов  
- [ ] Коэффициент: шаг 50; − не ниже base; подпись «+N руб»; подытог/итог/оплата  
- [ ] Товары без коэффициента  
- [ ] Ручная позиция + удаление  
- [ ] Оплата без мойщиков блокируется; с 2 мойщиками — ок  
- [ ] Аналитика: заказ 1000 ₽ / 2 мойщика → по 500; зарплата 40% → 200  
- [ ] Оператор: PIN, смена  
- [ ] OSK Shift/символы + физ. клавиатура  
- [ ] Старые данные БД после миграции целы
